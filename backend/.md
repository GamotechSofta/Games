# Platform Developer Handoff — PotLudo Integration

Ludo owns: rooms, matches, gameplay, local session tokens.  
Platform owns: user login, auth token, wallet balance, credit settlement.

Game frontend: `https://fashionbuddies.in`  
Game API: `https://api.fashionbuddies.in`  
Platform API: `https://api.aakda.in`

---

## 1. Launch URL (required)

```text
https://fashionbuddies.in/play/online?id=<USER_API_TOKEN>&game_id=2
```

| Field | Required | Description |
|-------|----------|-------------|
| `id` | **Yes** | Authenticated **user API token** (same value accepted as header `token` on detail/balance) |
| `game_id` | Recommended | Operator game id. Alias: `gameId`. Default: `2` |

**Critical:** `id` must be the same token your backend accepts in the `token` header on:

- `GET /service/user/detail`
- `POST /service/operator/user/balance/v2`

URL-encode the token if it contains special characters. Do not pass `user_id`, password, or a placeholder.

---

## 2. After launch

1. Browser opens Ludo with `id` + `game_id`.
2. Ludo client: `POST https://api.fashionbuddies.in/api/v1/identity/operator/session` with `{ "id": "<USER_API_TOKEN>", "gameId": 2 }`.
3. Ludo backend calls platform user-detail with that token.
4. On success, Ludo creates a local operator session (~16h) and seeds wallet balance.
5. On match start, Ludo debits entry fee via balance API.
6. Refunds / winner credits are published to RabbitMQ for the platform consumer.

---

## 3. APIs the platform must expose

Configure Ludo with:

```dotenv
APP_OPERATOR_BASE_URL=https://api.aakda.in
APP_OPERATOR_LOGIN_PATH=/operator/user/login
APP_OPERATOR_USER_DETAIL_PATH=/service/user/detail
APP_OPERATOR_BALANCE_PATH=/service/operator/user/balance/v2
APP_OPERATOR_GAME_ID=2
```

Use the API host (`api.aakda.in`), not the marketing site (`aakda.in`), unless both serve the same API routes.

### 3.1 User detail (required for session)

```http
GET /service/user/detail
token: <USER_API_TOKEN>
Accept: application/json
```

Success requirements:

- Top-level `status` must be **`true` (boolean)**
- User payload under `user`, or `data`, or top-level
- Required: `user_id` (aliases `userId`, `id`), `operator_id` (alias `operatorId`)
- Recommended: `balance`, display name, `currency` (defaults INR)

Example:

```json
{
  "status": true,
  "user": {
    "user_id": "12345",
    "operator_id": "1",
    "username": "PlayerOne",
    "balance": "5000",
    "currency": "INR"
  }
}
```

Self-test:

```bash
curl -i "https://api.aakda.in/service/user/detail" \
  -H "token: <TOKEN_YOU_PUT_IN_LAUNCH_id>" \
  -H "Accept: application/json"
```

### 3.2 Debit entry fee (required for match start)

```http
POST /service/operator/user/balance/v2
token: <USER_API_TOKEN>
Content-Type: application/json
```

```json
{
  "txn_id": "<ludo-generated-transaction-id>",
  "amount": 100,
  "description": "<reason>",
  "txn_type": 0,
  "ip": "<player-ip>",
  "game_id": 2,
  "user_id": "<from user detail>",
  "operator_id": "<from user detail>"
}
```

Success: response must include `status: true`. Debit the player wallet by `amount`.

### 3.3 Credits / refunds / payouts (RabbitMQ)

Ludo does not call an HTTP credit API. It publishes JSON to RabbitMQ.

Example defaults:

```dotenv
APP_OPERATOR_CREDIT_EXCHANGE=/games/admin
APP_OPERATOR_CREDIT_QUEUE_NAME=games_cashout
APP_OPERATOR_CREDIT_ROUTING_KEY=games_cashout
```

Message fields: `gameUserId`, `user_id`, `operatorId`, `amount`, `txn_id`, `txn_ref_id`, `game_id`, `token`, `ip`, `description`.

---

## 4. Platform checklist

- [ ] Pass real user API token in launch URL as `id`
- [ ] Token works on `GET /service/user/detail` with header `token`
- [ ] User-detail returns `status: true`, `user_id`, `operator_id`, `balance`
- [ ] Debit API accepts payload and returns `status: true`
- [ ] Confirm `game_id` (usually `2`)
- [ ] Consume RabbitMQ credit messages
- [ ] URL-encode token in query string

## 5. Smoke test

```bash
curl -i "https://api.aakda.in/service/user/detail" \
  -H "token: <TOKEN>" \
  -H "Accept: application/json"
```

Open:

```text
https://fashionbuddies.in/play/online?id=<TOKEN>&game_id=2
```

Confirm Network tab: `POST /api/v1/identity/operator/session` → **200** with `isOperatorSession: true`.

## 6. One-liner

Pass the authenticated user’s API token in the Ludo URL as `id`.  
Ludo sends that same value as the `token` header to `/service/user/detail` and `/service/operator/user/balance/v2`.
